# mess-index fuzz targets (bn-meo)

`cargo-fuzz` (libFuzzer) targets for mess-index's untrusted-bytes decode
surface: the columnar sealed-tier block codec (bn-1bn). Its own
`[workspace]`, same rationale as `crates/mess-log/fuzz`: cargo-fuzz's
nightly-only ASan build must never leak into the main workspace's stable
build.

## Targets

- **`fuzz_reassemble_block`** — `mess_index::columnar::Block::decode` and its
  `reassemble_*` methods. `data` is interpreted two ways, both run
  unconditionally on every input (see the doc comment at the top of
  `fuzz_targets/fuzz_reassemble_block.rs` for the exact format):
  1. **Blind**: `data` straight into `Block::decode` as a candidate
     compressed block + skeleton table. Invariant: never panic, never OOM.
  2. **Structured**: a tiny sub-format carves row payloads + a mutation list
     out of `data`, runs them through the real `encode_block` shredder (a
     *known* set of original payloads), and checks byte-exactness on the
     unmutated block plus **differential self-consistency** on a mutated
     copy — if a mutated block decodes and reassembles at all, re-shredding
     what it claims the rows are and reassembling *that* must reproduce the
     exact same bytes (this holds unconditionally by construction — raw
     fallback stores any row verbatim — so any divergence is a genuine
     "reassemble produced bytes the codec itself can't stand behind" bug).

## Running locally

```sh
# one-time (or whenever a richer seed set is wanted): regenerate the
# committed corpus from the real encoder.
cargo run --bin gen_corpus

# a real campaign — 10+ minutes:
cargo +nightly fuzz run fuzz_reassemble_block -- -max_total_time=600

# reproduce a crash file cargo-fuzz reports:
cargo +nightly fuzz run fuzz_reassemble_block artifacts/fuzz_reassemble_block/<crash-file>
```

## Local run log (bn-meo)

Two real, root-cause bugs were found and fixed in `mess-index`'s columnar
codec (`src/columnar/reassemble.rs`) within seconds of the first local run,
before the 10-minute campaign below — both are now regression-tested in
`src/columnar/tests.rs` and fixed at the parser (typed `CodecError`, not a
panic):

1. **`decode_raw` non-monotonic offset table panic.** The raw-fallback
   layout's decode only validated the *last* offset in its table against
   the payload region; an interior offset could be non-monotonic/huge while
   the last one still looked in-bounds, and `reassemble_range` then
   panicked slicing the buffer (`range end index ... out of range`). Fixed
   by validating every offset is non-decreasing, in addition to the
   existing last-offset bound (`decode_raw_rejects_non_monotonic_offsets`).
2. **Per-column block aggregate `ulen` allocation bomb.** Only each
   column's individual `ulen` was capped at `MAX_ULEN` (64 MiB); nothing
   capped the *sum* across up to `n_cols` (a u16, so up to 65535) columns.
   A directory naming many columns, each a tiny highly-compressible zstd
   frame claiming a large `ulen`, could force far more allocation in
   aggregate than the input bytes justify. Fixed by capping the running sum
   of every column's `ulen` at `MAX_ULEN` during directory parsing, before
   any column is decompressed (`decode_percol_rejects_aggregate_ulen_bomb`).

With both fixed, `fuzz_reassemble_block` ran clean for the required 10+
minute budget (`-max_total_time=600`, single worker, nightly toolchain,
`nightly-2026-04-29`):

- **Execs**: `Done 2298672 runs in 601 second(s)` — lower per-second
  throughput than `crates/mess-log/fuzz`'s raw byte-slice targets is
  expected here: each exec does real zstd compression (`encode_block`) plus
  a full decode/reassemble/re-shred/re-decode round trip, not a single
  bounds-checked parse.
- **Findings**: 0 crashes, timeouts, OOMs, or leaks during the 10-minute
  campaign (run after both fixes above landed) — a clean `artifacts/`
  directory on a fresh checkout.

## Corpus

`corpus/fuzz_reassemble_block/` holds a small, hand-picked seed set —
real `encode_block` output (whole-block and per-column layouts, forced raw
fallback, deeply-nested-payload fallback) for the blind check, plus bytes
laid out in the structured sub-format (real rmp-serde-named payloads
mirroring `spikes/perf_compress/src/workload.rs` / `src/columnar/tests.rs`'s
corpus shapes) for the structured check — generated by `gen_corpus.rs`
(`cargo run --bin gen_corpus`), not hand-copied hex. Kept minimal per the
bn-gux protocol (`crates/mess-log/fuzz`'s prior art); libFuzzer's own
coverage-guided mutation is expected to grow a much larger corpus
locally/in CI, intentionally **not** committed.
